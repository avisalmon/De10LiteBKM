FFT Lab: architecture spec

What each module is, what crosses between them, where every bit of state lives, and the budgets. Written for someone who will change the lab or build the next one on it. The overview has the block diagram and the measured results; the numbers here come from the same build.

Requirements

  • Make six test signals (sine, square, triangle, saw, spikes, noise), 256 samples at f = N × 12.5 Hz with N = 0..1023 (up to 12,787.5 Hz at a notional 25.6 kHz sample rate), with or without a Hann window.
  • Show the signal as a scope trace, and its spectrum twice side by side: our own 256-point FFT and Altera's FFT II IP, 128 bars of 100 Hz each, in dB (10 dB per division) or linear.
  • Give both FFTs the same samples in the same clocks, and time each one from the first sample in to the last result out, in clocks and in microseconds.
  • A new measurement every screen frame (59.5 Hz), computed inside the vertical blanking time, with no frame buffer for the picture.
  • Controls on the shield (wheel, joystick, A, B, Start, Select) and the board (KEY0, KEY1), and the same over USB; the LEDs, the 7-segment display and the buzzer follow the settings.
  • Keep running when the evaluation IP stops: notice it, say so on the screen and with the shield's LED, and carry on with our FFT.
  • Testable to the bit without hands: a bit-exact Python model; testbenches that render the screen; on the board, a report line and a screen capture over USB, compared with the model.
  • Quartus Prime Lite 17.1 with the free evaluation of the FFT IP, nothing paid. The project stands on its own: its only shared code is lib/.

The screen's memories answer one clock after the address, so lab_draw addresses them with the next scan pixel (pxl_x + 1) and uses the answer for the current one: no pixel is shifted.

All the tables come from sim/lab_model.py, the same code that predicts the screen, so the hardware and the model cannot disagree about a table. mag_rom's file is binary ($readmemb): 7-bit words are not whole hex digits, and hex makes Quartus print 4,096 warnings.

State machines, pipelines and encodings

The frame (lab_engine)

  1. Start. At tick, unless hold is on: frame_go = start && !run && !g_busy && rcnt == 0 && !restart_pend. The shape, frequency, window and scale are latched for the whole frame (f_*), and run is set.
  2. Samples. wave_gen streams n = 0..255 with valid / ready. A sample moves (tr = g_valid && (sink_ready || dead)) into the IP's Avalon-ST sink (sop at n = 0, eop at n = 255, imaginary part 0) and into fft_r2 in the same clock. The timer t is 1 on the first move and counts every clock (it stops at 99,999).
  3. Scope. On every move after the first, entry n − 1 of scope_mem gets the span from the previous sample's y to this one's; after sample 255, entry 255 gets a single point.
  4. Bars. Each FFT's results go through its own mag_px (6 clocks) into its bar memory. Bins 128..255 mirror the lower half for a real input and are not drawn. The tallest bar and its bin are kept (the lowest bin wins a tie).
  5. Times. dclk = t when our bin 255 leaves fft_r2; iclk = t at the IP's eop, together with its block exponent.
  6. Watchdog. While the IP has not finished, wd counts; at WATCHDOG (20,000 clocks) the IP is marked dead. From then on it is ignored (g_ready is 1, so our FFT can never be stuck waiting for it) and its numbers are 0.
  7. Publish. When ours is done and the IP is done or dead: run clears, pub is high for one clock, and the frame's settings and results go to the r_* registers that the screen, the digits and the report read. r_ip_ok = !dead && !(in_nz && !out_nz): an IP that turns a non-zero input into all zeros is not ok either.
  8. Digits. lab_digits turns the 12 published numbers into decimal (about 250 clocks for all 12); a report line asked for with R is sent when they are ready.

The IP's reset: ip_rst_n is low for IP_RESET_CLOCKS (1,000) after the PLL locks, and again after a restart (KEY0 or D), which waits for the running frame to end and clears dead. With hold on, no frame starts: the memories and the published values stay as they are.

4MULTfour products: c·br, s·bi, c·bi, s·br (4 hardware multipliers)ADD

Butterfly bf (0..127) of stage s (span = 2s): j = bf mod span, top = (bf / span) · 2 · span + j, bottom = top + span, twiddle k = j · 128 / span. One butterfly takes 5 clocks, so a frame is 256 (load) + 1,024 × 5 + 256 × 3 (unload) + 1 = 6,145 clocks. Every stage halves its results, so the output is FFT(x) / 256 and nothing can overflow. The IP takes 1,637: 1,381 from the first sample in to the first result out, then 256 results.

lab_ctrl: the controls

Priorityone always block, later lines win: USB letters, then KEY0, then the buttons, then the wheel; Left over Right
Buttonsread at tick, acting on the press (edge): Right or KEY1 next shape, Left previous (both wrap); A window, B dB / linear, Start hold, Select sound (toggles)

The wheelat 1 kHz: wacc += ws − wacc / 64 (a 64 ms smoothing), wf = wacc / 64; q = wf / 4 (0..1023) with hysteresis (q stays while wf is within 4q − 2..4q + 5)
Who sets the frequencythe wheel takes over (follow) only when it is turned: when q is 2 or more steps from q_ref, the q at the last time the frequency was set another way (a step, N, KEY0, D). For the first 512 ms after power-up q_ref follows q, so the wheel's start-up does not count as a turn.

Encodings

Shape0 sine, 1 square, 2 triangle, 3 saw, 4 spikes (one sample of A per period: a comb of equal harmonics), 5 noise (xorshift32, seed 0x2545F491, ¾ of its top 16 bits; it steps every sample, whatever the shape). All peak at A = 24,576 (¾ of full scale).
FrequencyN = fq, 0..1023: f = N × 12.5 Hz, bin = N / 8 (100 Hz a bin). 256 samples = 10 ms on the scope. N = 80 is 1 kHz, bin 10.
Scope entry14 bits {smaller y, larger y}, 7 bits each; the screen draws the trace in a column where Y is between them
Bar heightmag_rom[{lin, e, m}] for the power r = 2e − 44 · (1 + (m + 0.5) / 32) of full scale: dB: round(10 log10 r) + 90, 1 px per dB; linear: round(90 √r). Both clamped to 0..90.
Scale offsetsours: e = p + 16 (our output is divided by 256); the IP: e = p − 2 · exp (its output is scaled by 2exp); +2 for both with the window, which halves the amplitude. Both panels then share one full scale.
Times on screenclocks as 5 digits, and microseconds (clocks × 40 ns) as uuuu.uu
LEDsLEDR9 sound, LEDR8 hold, LEDR7 linear, LEDR6 window, LEDR5..0 the shape, one-hot (LEDR0 sine .. LEDR5 noise). Live settings.
7-segmentthe frame's frequency in Hz with one decimal (1000.0): the point on HEX1, leading zeros blank
Buzzera 32-bit phase accumulator adds fq × 2147 per clock (232 × 12.5 Hz / 25 MHz = 2147.5): its top bit is a square wave at the live frequency, 0.02 % low

The report line, 126 characters, sent on R (this one is the defaults frame on the board; one line, shown in two here):

FFTLAB SHAPE=0 N=0080 HZ=01000.0 WIN=0 LIN=0 HOLD=0 OUR_CLK=06145 OUR_PK=010/087
IP_CLK=01637 IP_PK=010/088 IP_EXP=-08 IP_OK=1

All the values are the published frame's except HOLD, which is live. OUR_PK and IP_PK are bin / height in pixels of the tallest bar; IP_EXP is the IP's block exponent; IP_OK is 0 when the IP was dead or answered with zeros. sim/board_check.py sends settings, reads this line and the screen, and compares both with the model.

Budgets

Logic7,183 / 49,760 LEs (14 %); 3,929 registers; 26 / 288 9-bit multipliers (9 %). The IP is 1,734 LEs, our FFT 398; each uses 8 multiplier elements.
Memory1,035,592 / 1,677,312 bits (62 %), 137 / 182 M9K (75 %): the lab 19 M9K, the capture buffer 114
Clocks per frame28,000 available: from the start of vertical sync to the first visible line (35 lines × 800). A normal frame needs about 6,400 (computed: our 6,145, the pipelines, about 250 for the digits), 23 %. The worst in simulation is 20,253, an IP that never finishes (the watchdog's 20,000 and the digits), 72 %. An IP that took no input at all would start our FFT only after the watchdog: about 26,400 (computed), still inside.
Timingmet at every corner. The 25 MHz domain's Fmax is 38.34 MHz (slack 13.9 ns); the smallest setup slack of any clock is 2.85 ns, the smallest hold slack 0.10 ns
Headroom86 % of the logic and 262 multiplier elements are free; leaving out the capture buffer frees 114 M9K. A 1,024-point fft_r2 would not fit the frame (about 29,700 clocks): it would need a faster clock or a second butterfly.

Design decisions

  • The same sample into both FFTs, in the same clock. The IP's sink_ready paces both, so the comparison is fair by construction: same input, same start, one timer.
  • All the work in the blanking time, no picture frame buffer. The screen is drawn per pixel from 5,376 bits of scope and bar memory instead of a 320 × 240 picture (921,600 bits), and nothing can tear.
  • Our FFT is simple on purpose. One butterfly, 5 clocks each, in place: 3.75 times slower than the IP, with about a quarter of its logic (398 LEs against 1,734). The contrast is the lesson; the screen shows both numbers.
  • Halving at every stage against block floating point. Ours divides by 2 at each of 8 stages and cannot overflow, at the cost of precision on small signals; the IP scales a whole block by 2exp. Measured as the SNR against numpy in examples/11_fft (three tones): the IP 66.9 dB, ours 56.3 dB. The offsets in mag_px put both on one scale.
  • A table for the bar heights. No log, square root or divider: the top bit and the 5 bits under it address one 4,096 × 7 ROM that holds both the dB and the linear scale, with one read port per FFT.
  • A watchdog on the IP. The evaluation IP stops when its time is up; the lab must keep running, show our FFT, and say what happened instead of freezing.
  • A bit-exact Python model. It writes every table and predicts every pixel and report line, so each test is an exact comparison, in simulation and on the board.
  • ModelSim records the IP, Icarus replays it. The IP's simulation model runs in ModelSim only; its recorded outputs (sim/ip_vectors.hex, played back by sim/fft256_replay.sv) let the fast Icarus testbench include the IP exactly.
  • The capture buffer stays in. 114 M9K, but it is what lets board_check.py compare the real screen with the model pixel by pixel.
  • The evaluation IP, on purpose. It is what Quartus Lite gives for free. The price: a time-limited .sof that runs while the programmer stays connected, and no .pof, so no flashing. A version with only our FFT could be flashed.
  • Known signals rather than the ADC. Generated input can be predicted to the bit; a microphone or ADC input could not be checked that way.
  • The project stands on its own. It has its own copy of fft_r2 and of the IP generator rather than reaching into examples/; only lib/ is shared.
