Requirements

  • An RV32I CPU complete enough to run compiled C: all base integer instructions, byte / half / word memory access, a flat 32-bit address space. No privileged mode, no interrupts, no CSRs, no M extension.
  • 32 KB of RAM for code and data, initialised at power-up with a program, rewritable over JTAG while running.
  • A text screen of 80 × 60 cells with foreground and background colours, drawn by hardware from a RAM the CPU writes.
  • Memory-mapped input (the pad, keys, switches, time, randomness) and output (digits, LEDs, buzzer, UART, exit).
  • A toolchain in the repo, Python only: assembler, C compiler, simulator; one command from C to an image.
  • Every program runs identically on the simulator and on the RTL (lock-step traces), and the board is testable over USB.
  • Tetris, playable with the shield's pad, at 60 frames per second.

The bus

SignalDir (CPU)Meaning
bus_reqoutan access is wanted; held until bus_ack
bus_we, bus_addr[31:0], bus_wdata[31:0], bus_be[3:0]outwrite / read, the word address (bits 1:0 are 0), the data (a byte or half is replicated across the word), the byte enables
bus_rdata[31:0]inread data, valid in the ack clock
bus_ackinone clock after the first req clock (ack <= req && !ack)

A write is performed by the slave in the first req clock (first = req && !ack); a read is issued then and answered in the ack clock. The CPU drops req after the ack, so a slave never sees a second access before it finished the first. A slower slave may delay its ack; nothing else changes. Addresses are decoded on addr[31:28]: 0 = RAM, 1 = TEXT, 2 = I/O; anything else reads 0 and ignores writes.

The CPU

StateClocksDoes
S_FETCH2req with pc; on ack ir <= rdata
S_EXEC1decode ir combinationally: immediates (I S B U J), rs1v / rs2v, the ALU (add sub sll slt sltu xor srl sra or and; the I forms use the immediate), the branch condition, pc_next. LUI AUIPC JAL JALR OP OP-IMM: write rd (if not x0), pc <= pc_next, back to FETCH. LOAD / STORE: to S_MEM. ecall / ebreak: S_HALT. Illegal opcode: S_HALT with fault.
S_MEM2req with rs1 + imm (word-aligned on the bus, be by size and addr[1:0]); on ack a load's byte / half is selected by addr[1:0] and extended by funct3; pc <= pc + 4
S_HALT-halted = 1 until reset; the top blinks LEDR9

Register file: regs[1:31] as flip-flops, read combinationally, reset to 0. x0 reads 0. Trace port: a pulse with pc, rd and the value for each register write (the testbench writes it to the trace file). No misaligned access support: the compiler and the runtime never produce one; a misaligned load reads the aligned word (documented, not trapped). fence is a no-op.

The text screen

For the scan pixel (pxl_x, pxl_y) the cell is (pxl_x >> 3, pxl_y >> 3); the address of the next pixel's cell (row × 80 + col, computed as row × 64 + row × 16 + col) goes to the text RAM, whose answer arrives for the current pixel. The glyph row comes from font8x8 (ASCII 0x20..0x5F; lower case folds up) for characters below 0x80; for 0x80..0x83 it is made in logic: full block, inner 6 × 6 block, checkerboard shade, 1-pixel frame. The pixel is the foreground colour where the glyph bit is set, else the background; both through the 16-entry CGA palette (RGB444). Outside 640 × 480 the output is black.

The CPU reset is asynchronous (the PLL lock) but released synchronously through two flip-flops; 'H' holds it, 'R' pulses it for 32 clocks.

Software: calling convention, runtime, the C subset

Registersa0..a7 arguments and a0 the result; ra the return address; s0 the frame pointer; sp the stack (16-byte aligned frames); t0..t6 scratch (the runtime uses them); s1..s11 unused by the compiler
Framesp -= size; ra at size-4(sp); s0 at size-8(sp); s0 = sp + size; parameters are spilled to the frame; locals at s0-12 and below (4-byte slots, arrays in place)
Expressionsevery expression leaves its value in a0; binary operators push the left value, evaluate the right, pop the left into a1; a constant right operand uses the immediate forms; literal-literal is folded
Runtime (crt0.s)_start at 0: sp = 0x8000, zero .bss, call main, write EXIT with its return value. __mul (shift-add), __udivmod (restoring), __div / __mod (signs like C), __udiv / __umod
Typesint / unsigned int 32-bit, char / unsigned char 8-bit (lb / lbu), pointers 32-bit, arrays of one or two dimensions; char promotes to int on load; casts to char truncate and extend
Acceptedglobals with constant initialisers (arrays, strings, string pointers), functions (up to 8 parameters, prototypes), if / else, while, do, for (declaration in init), switch / case / default, break, continue, return; all operators but the comma; sizeof; #include, #define (with arguments), #ifdef / #ifndef / #else / #endif, #undef
Refusedstruct, union, enum, typedef, float, long, goto, function pointers, variadic functions, local array initialisers, the comma operator (an error with the line)
Imageone segment: crt0, then the C code, then .data, then .bss between __bss_start / __bss_end; the assembler writes 8,192 words

The lock-step test method

Trace lines: pc rd value for a register write (the simulator adds ~ when the value came from FRAME, CYCLES, RANDOM or BUTTONS) and pc W addr value be for a store. The simulator writes it per instruction; the testbench from the CPU's trace port and the bus. trace_compare.py demands identical lines, except: a ~ line needs only the same pc and rd; a store needs equality on the enabled bytes. Any divergence prints both traces around it with line numbers; the .sym file maps the pc to a function. The method found the CPU's only bug and three compiler bugs; it is the project's regression test (tests/test_riscv_tetris.py, Icarus in CI).

Design decisions

  • Multi-cycle, not pipelined. Three states, no hazards, no forwarding, one bus port: the CPU is 300 lines you can single-step in a waveform, and it is fast enough by a factor of fifty for a game. Speed was not the goal; proof was.
  • One bus protocol for everything. RAM, text and I/O all look the same to the CPU; a new peripheral is a case line in rv32_soc.sv and a line in memmap.py.
  • The toolchain in Python, in the project. A gcc cross-compiler is 300 MB and a black box; the user of this BKM learns more from a 1,300-line compiler whose output they can read, and the AI can extend it when a program needs something. The price: a C subset and slow code; both are documented and tested.
  • Lock-step traces as the definition of correct. The simulator is the specification the RTL must match; the trace format is the simplest thing that catches every register and memory effect.
  • Programs over JTAG. ENABLE_RUNTIME_MOD on the RAM plus two letters make the edit-compile-run loop ten seconds; the FPGA is rebuilt only when the hardware changes.
  • A text screen, not pixels. 76,800 bits of RAM, a few lines of logic, and a C program draws with a store.
