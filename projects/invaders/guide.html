Space Invaders: user guide

From the repo to the game on your board, and everything you can do with it afterwards. Every command runs from the repo's root folder in the env virtualenv; the chat does them for you if you ask.

What you need

  • A DE10-Lite with the LCD / game-pad shield on its Arduino header (the game needs the screen and the game pad). A VGA monitor on the board's VGA port shows the same picture.
  • Quartus Prime Lite 17.1 installed as in stage 1 of the BKM (python scripts/doctor.py shows no FAIL).
  • The repo cloned, env created (setup-my-computer does this), the board on the USB cable.

Build and load it

The sources are in the repo; one build makes the bitstream (the repo keeps none, they are 3 MB each):

python scripts/de10.py build   projects/invaders    # about 3 minutes; prints resources and timing
python scripts/de10.py program projects/invaders    # over the USB-Blaster; lasts until power-off

From the archive instead (for example in the Quartus GUI): Project → Restore Archived Project → invaders.qar, then Processing → Start Compilation, then Tools → Programmer with output_files/invaders.sof. The archive holds the sources, the settings and the sprite generator.

What you should see right after loading: the attract mode, as on the arcade. The score line at the top, then PLAY and SPACE INVADERS typed one letter at a time, the score advance table, a short demo game in which the cannon plays itself, then INSERT COIN, and round again. The 7-segment digits show 0000 (the score) and 00 (the credits).

Play

Select (shield) or KEY1a coin: CREDIT counts up, up to 99. The first coin stops the attract mode.

LEDR0..6one LED per spare ship
LEDR7, 8, 9fast-forward (a preset is running), paused, invincible (test modes, set over USB)

Buzzerthe march (four low notes, faster as the invaders thin out), the shot, a hit, the saucer's warble and its explosion, the extra ship, your cannon's explosion

The switches are read when a game starts, so set them before you press Start.

Rules, briefly: 55 invaders in five rows march sideways and step down at each edge. The bottom two rows are worth 10, the middle two 20, the top row 30. The fewer are left, the faster they march; the last one is very fast. They drop three kinds of bombs; the four shields stop bombs and shots, and wear away where they are hit. The flying saucer crosses the top from time to time, worth 50 to 300 points by the arcade's table, chosen by how many shots you have fired. Clear the rack and the next one starts lower. The game ends when you lose your last ship or the invaders reach the ground. The high score stays until the board loses power.

Play and test over USB

The game listens on the JTAG UART, the same link the BKM uses for logs. Each letter is one command:

python scripts/de10.py send c        # a coin; then s to start
python scripts/de10.py send l        # left for 16 frames; r = right
python scripts/de10.py send a        # fire
python scripts/de10.py send p        # pause / resume
python scripts/de10.py send i        # invincible on / off
python scripts/de10.py send m        # mute / unmute
python scripts/de10.py send 5        # test preset 5 (next section)
python scripts/de10.py send "?"      # the status line (buttons, switches, frame counter)
python scripts/de10.py screen x.png  # the screen as the board shows it, saved at 640 x 480

Invincible means bombs pass through the cannon, and a rack that lands starts a new rack instead of ending the game. This is how the AI tested the game without hands, and how you can script a test of your own: send letters, capture, look.

The ten test presets

A preset is a known moment of a game. Sending a digit resets the game as at power-up (the credits and the high score go back to zero), runs that many game steps as fast as the logic can, then pauses. Preset 0 stays in the attract mode. Presets 1 to 9 start a game at once, played by the machine's own player (the attract mode's demo moves), with 3 ships and the extra ship at 1,500 whatever the switches say, and invincible, so a rack that lands starts the next one. While a preset runs, LEDR7 is lit, the controls count as released and the buzzer is quiet; at the end LEDR8 lights (paused). The simulation runs the same steps, so the board and sim/preset_N.ppm show the same picture, pixel for pixel.

On the board a preset takes well under a second: the steps run back to back, a few hundred clocks each on average. In the simulation preset 9 alone takes about 8 minutes. Press p to play on from the paused moment; you play it yourself, and the cannon is no longer invincible.

Keep it after power-off

Loading with program lasts until the power goes; to make Space Invaders the design the board starts with:

python scripts/de10.py flash projects/invaders      # writes and verifies output_files/invaders.pof

It replaces whatever was in the flash before (the chat asks first). Loading other designs with program afterwards does not touch it; the game returns at the next power-up. The library's flash-design skill and example 13 explain the .pof.

Run the simulation

python scripts/sim.py projects/invaders/sim/tb_invaders.sv -D QUICK   # about 3 minutes; PASS
python scripts/sim.py projects/invaders/sim/tb_invaders.sv            # all ten presets; 26 minutes

It plays scripted games through the game, the screen and the sound modules together (inv_logic, inv_draw, inv_sound; everything but the board's I/O). Each game step starts with a tick, as in the vertical blank; a frame is drawn by walking the screen's pixel counter across all 640 × 480 positions, one per clock. It writes the frames next to the testbench: attract.ppm, demo.ppm, credit.ppm, intro.ppm, play.ppm, columns.ppm, wave2.ppm, gameover.ppm, rack_low.ppm and preset_0.ppm to preset_9.ppm (the QUICK run stops at preset_2.ppm). Open them with any image viewer, or convert with Pillow (Image.open("x.ppm").save("x.png")). There is no waveform file: a game is hundreds of millions of clocks, so the testbench checks the rules and draws pictures instead. The checks it makes are listed on the overview.

To compare the board with the simulation, run the same preset on both and let the script count the differences:

python scripts/de10.py send 5
python scripts/de10.py screen x.png
python scripts/screen_check.py x.png projects/invaders/sim/preset_5.ppm --diff d.png

It prints 0 of 76800 pixels differ and OK: the screen matches; any pixel that differs is drawn in red in d.png.

Change it

You wantWhere
other picturesevery picture is text art in assets/make_sprites.py (# lit, . dark). Edit it, run python projects/invaders/assets/make_sprites.py, check assets/sprites_preview.png, rebuild. Keep the sizes, or adjust the boxes in inv_layers.sv.
other coloursthe overlay bands are parameters of inv_draw.sv (RED_Y0, RED_Y1, GREEN_Y0, GREEN_Y1, SHIPS_X0, SHIPS_X1); the colours are the 12'hF22, 12'h2F2 and 12'hFFF next to them
faster or slower invadersthe rack moves one invader per game step, like the arcade, so the fewer are left the faster they go. The step size is dx in inv_logic.sv (2 pixels; 3 for the last invader going right). march_delay() sets only the tempo of the march sound.
more or fewer bombsreload_rate() in inv_logic.sv, by score
the saucerSC_TIME (steps between saucers) and sc_table() (its values) in inv_logic.sv
the extra shipBONUS_HI, BONUS_LO in inv_logic.sv (BCD, so 16'h1500 is 1,500)
other soundsinv_sound.sv: one square wave whose half period changes once a frame; half = 25,000,000 / (2 × Hz)
two playersnot built: the arcade keeps a rack and four shields per player. The chat can add it.

After any change: simulation (PASS), build (timing OK), program, play. The testbench renders the frames, so most mistakes show up as a picture before the board is involved.
