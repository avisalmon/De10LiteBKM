11 · FFT: Altera's IP vs our own

Can you use Altera's FFT IP on the DE10-Lite, and what does it cost compared with writing your own? Both run here on the same 256-point signal, and the PC checks both against numpy.

Verified on the board 2026-10-24 Quartus Prime Lite 17.1 No shield needed Skills: use-ip-library, compute-fft
Download fft_time_limited.sof Download fft.qar (full project, with the generated IP)

The FFT IP is a licensed Altera core. Quartus Prime Lite compiles it in OpenCore Plus evaluation mode: the build makes fft_time_limited.sof instead of fft.sof, and the design runs only while the programmer stays connected ("tethered": quartus_pgm keeps running) or for a limited time. Our own FFT has no such limit.

Reading it: the IP is about 4 times bigger in logic, 4 times faster, and 10 dB more accurate (block floating point scales only when the numbers need it; our FFT halves at every stage and loses bits on a signal that never needed it). Our FFT's 56 dB is about 9 good bits on a 16-bit signal: plenty for a spectrum display, not for audio analysis. Both ran on the board; our FFT gives exactly the same numbers in simulation and on the board.

Using an IP from the library, without the GUI

Altera's IP cores live in C:\intelFPGA_lite\17.1\ip\altera. Each has a _hw.tcl file whose add_parameter lines are the settings. ip-generate builds a configured copy into your project:

python examples/11_fft/ip/generate_fft_ip.py
→ ip-generate --component-name=altera_fft_ii --output-name=fft256 --file-set=QUARTUS_SYNTH
    --component-parameter=length=256 --component-parameter=data_flow=Burst ... → ip/fft256/fft256.qip

Add the .qip to the project (src/extra.qsf: set_global_assignment -name QIP_FILE ip/fft256/fft256.qip) and instantiate fft256. When a setting is not allowed for the chosen architecture, ip-generate prints an Error line saying why (here: Burst needs Bi-directional and Natural output order).

Talking to the FFT IP

  • In: one sample per clock while sink_ready is high: sink_valid, sink_sop on the first sample, sink_eop on the 256th, sink_real/sink_imag. inverse = 0 for the forward FFT.
  • Out: source_valid with source_sop/source_eop around 256 results in natural order, and source_exp, the block exponent.
  • Scale: the true FFT value = output × 2−exp. Here exp = −7, so ×128. (Checked: with that scale the error against numpy is 66.9 dB below the signal.)

Our FFT in brief

src/fft_r2.sv: the 256 samples are written into one RAM at bit-reversed addresses; then 8 stages × 128 butterflies, each reading two values and a twiddle (cos, sin in Q15 from assets/twiddle.hex), multiplying with 4 multipliers, and writing back (a + W·b)/2 and (a − W·b)/2. Halving every stage makes overflow impossible; the price is precision. Ideas to make it better: halve only when a stage would overflow (block floating point), or two butterflies in parallel with a second RAM.

Bugs met on the way (each now a gotcha)

  • An unsized number in a concatenation. {sign, 8'h30 + (m / 10), ...}: the bare 10 is 32 bits, so each term became 32 bits and the text came out as zero bytes. Size everything inside { }.
  • The later assignment wins. if (go) t <= 0; ... if (run) t <= t + 1; in one block never reset the counter.
  • A third read port kills block RAM. Reading ram[cnt] directly (not through a clocked port) would have turned the RAM into 8,192 flip-flops.

Run it

python scripts/de10.py program examples/11_fft/fft_time_limited.sof    (keeps running: tethered; stop it with Ctrl+C)
python scripts/de10.py send R 8 > logs/fft_dump.txt                    (in a second terminal)
python examples/11_fft/sim/fft_data.py check logs/fft_dump.txt

Build it yourself

python examples/11_fft/sim/fft_data.py make          # input.hex, twiddle.hex
python examples/11_fft/ip/generate_fft_ip.py         # the IP
python scripts/new_project.py examples/11_fft fft_top --lib print seg7
python scripts/de10.py build examples/11_fft

Test without the board

python scripts/sim.py examples/11_fft/sim/tb_fft_r2.sv
python examples/11_fft/sim/fft_data.py check examples/11_fft/sim/diy_dump.txt     → DIY 56.3 dB, bins 10 37 85
