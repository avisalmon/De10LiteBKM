06 · The 64 MB SDRAM

The DE10-Lite has 64 MB of SDRAM next to the FPGA: about 40 times all the FPGA's block memory together. This example drives it with a small controller written here, and tests every one of its 33,554,432 words.

Verified on the board 2026-10-24: all 32M words checked Quartus Prime Lite 17.1 No shield needed Skill: use-sdram
Download sdram.qar (full project)

The repo keeps the full project (.qar, plus the sources here) but no prebuilt bitstream: one build (a few minutes) makes the .sof on your computer.

Yes, it is DRAM

SDRAM = synchronous dynamic RAM: every bit is a tiny capacitor that leaks, so each row must be refreshed every 64 ms (the controller does it every 7.8 µs, one row at a time), and a word is reached in steps: open the row (ACTIVATE), read or write the column, close the row (PRECHARGE). The chip on the board is an IS42S16320: 4 banks × 8,192 rows × 1,024 columns × 16 bits.

PASS 03 delay=5 64K words errors=00000000 clocks=001941A0
PASS 04 delay=6 64K words errors=00000000 clocks=001A4335
PASS 05 delay=7 64K words errors=00000000 clocks=001B46C4
PASS 06 delay=4 32M words errors=00000001 clocks=307DA7D4     ← the whole chip; the 1 error is the one SW0 injected
PASS 07 delay=4 32M words errors=00000001 clocks=307DA7D6
  • The first six passes measure the read delay (clocks from the READ command until the data is sampled) on 64K words: 2 is too early, 3 is the first that works. The controller uses 4, one clock of margin, which is also what the simulation model predicted. (5 to 7 "work" only because the data bus keeps its last value after a read.)
  • A full pass writes and reads all 33,554,432 words in 0x307DA7D4 clocks = 16.3 s at 50 MHz: about 4 million accesses a second, 8 MB/s. Simple and safe, not fast; a burst controller is 10 to 20 times faster.
  • SW0 was up during this run: the design writes one wrong word per pass on purpose, and the test finds exactly that one. A full pass with SW0 down (expected: 0) is still to be run by someone at the board; the 64K passes above, which do not include the injected address, show 0. Resources: 1,664 logic elements (3 %). Timing: no negative slack.

Block diagram

The controller (lib/rtl/sdram_ctrl.sv)

  • Clock: 50 MHz logic; DRAM_CLK is the same clock shifted 180° by the PLL, so the SDRAM samples our signals in the middle of their 20 ns: about 10 ns of margin both ways, no fragile I/O timing analysis needed. The pins use the I/O cells' own registers (FAST_OUTPUT_REGISTER / FAST_INPUT_REGISTER in src/extra.qsf) so their timing is the same in every build.
  • Start-up: wait 200 µs, PRECHARGE ALL, 8 AUTO REFRESH, LOAD MODE (burst 1, CAS latency 3).
  • Each access: ACTIVATE the row, READ or WRITE the column with A10 = 1 (auto-precharge), wait. About 9 clocks for a write, 13 for a read.
  • Interface: when ready, raise req for one clock with we, addr = {bank, row, column}, wdata; reads come back as rvalid + rdata.

What it took (three real bugs, each found on the board)

  1. Requests swallowed by refresh. The test saw ready, raised req for one clock, and in that very clock a refresh became due: the controller refreshed and the request vanished; the test hung. Signal Tap showed the test waiting and the controller idle. Fix: the controller now latches every request and serves it after the refresh.
  2. Every write one address late. The test raised req and moved its address counter on in the same clock, so the controller (which takes the request a clock later) saw the next address. Reading address 1 twice proved it. Fix: a separate request-address register set together with req.
  3. A name used before its declaration became a silent 1-bit wire. Now the file starts with `default_nettype none, which turns that into a compile error.

The simulation (lib/sim/tb_sdram_ctrl.sv with the SDRAM model lib/sim/sdram_model.sv, which drives read data only in the datasheet's valid window) passed all along: it fails with read delay 3 or 5, so it checks the timing, but it could not see bugs that lived in how the test talked to the controller. The board and Signal Tap could.
