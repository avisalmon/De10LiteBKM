03 · RAM: single-port and dual-port

Memory you can write. A single-port RAM checks itself about 3,000 times a second, and a dual-port RAM is a frame buffer: written at 50 MHz by a little paint program, read at 25 MHz by the screen.

Verified on the board 2026-10-24 Quartus Prime Lite 17.1 LCD shield (game pad) or VGA Skill: build-ram
Download ram.sof Download ram.qar (full project)

The three RAM templates

All three are plain Verilog written the way Quartus recognizes as block memory (M9K). They live in lib/rtl/:

ModulePortsUse it for
ram_spone address, write + read, one clockscratch memory, tables you update, a CPU's data RAM
ram_dpone write port, one read port, each with its own clockframe buffers, FIFOs, passing data between clock domains
ram_tdptwo independent read/write ports, two clocksshared memory between two engines (e.g. CPU and DMA)
ram_dp #(.WIDTH(12), .AW(15), .DEPTH(19200)) fb (
  .wr_clk(clk_50), .wr_addr(wr_addr), .wr_d(wr_d), .we(we),      // paint
  .rd_clk(clk_25), .rd_addr(rd_addr), .rd_q(pixel));              // screen

DEPTH keeps the memory to what you need: 19,200 words instead of the 32,768 a 15-bit address could reach. Every read answers one clock after the address, so the screen asks for the next pixel, exactly as with ROMs (example 02).

Things learned building it (each one cost a build)

  • Wait for the PLL before writing block RAM. The first version filled the frame buffer the moment the FPGA started: the screen stayed black, although simulation passed. The PLL was not locked yet, and writes on an unsettled clock were lost. The fix: paint waits for locked (synchronized into its clock). Found with Signal Tap (the painter was idle and the VGA output black) and a simulation of the same fill (which passed): the difference had to be real hardware.
  • Quartus 17.1 ignores initial values on output ports. output reg [7:0] cx = 80 starts at 0, silently. Set start values in a reset branch instead (internal reg x = 5; works).
  • The game-pad ADC needs a 50 MHz clock and two fixes in the template's ADC IP (it ran the ADC at 12.5 MHz, above the 10 MHz spec, and missed Altera's timing constraints). Fixed in lib/rtl/adc; timing is now clean.
  • Prove the checker. A memory test that never reports errors may just be broken. SW0 injects one bad bit per pass, and the count climbs by exactly one per pass.

Measured on the board

SW0 up:    RAM BIST passes=00005F5E errors=00005F5E last=0001     ~3,050 passes / s, one error per pass, as injected

SW0 down (no injection, errors must stay 0) is verified in simulation (tb_ram_bist.sv); the board run with SW0 down is still to do.

Screen read back over USB: the test picture, pixel for pixel (image above). Resources: 7,193 logic elements (14 %), memory 78 % (screen read-back buffer 56 %, frame buffer 14 %, BIST RAM 8 %). Timing: no negative slack.

python scripts/new_project.py examples/03_ram ram_top --lib display gamepad debug print mux bcd sevenseg ram
